07 / Synthesis
Mode — convergence · 3 themes · 4 decisions

Three themes, one floor收敛 — 六个方向，挖到同一块地板

115 个想法最后没有变成 115 个待办。它们收成三条主线、一个复发证据、一层当天可发的补丁，以及一层防止第四次复发的架构。真正非显然的结论在最后：两次修复都在修 sheet 停在哪，而缺陷是「只有 sheet 能接收输入」。

THEME01

Nobody owns the wait没有人拥有超时与所有权

卡死不是「慢」，而是没有任何东西拥有超时与所有权 —— RPC 无 deadline、gate 无租约、attempt 无终点。于是「等」变成一个没有边界的默认状态。

RPC: no read timeoutgate: no leaseattempt: no terminal statesupervisor: single
THEME02

Silence looks exactly like a freeze没有可见性，静默与冻结不可区分

连接阶段、谁持有 gate、等了多少秒全都没暴露，所以任何一次静默都表现为不可区分的冻结。用户无法判断该等、该杀、还是该重启。

stage: hiddengate holder: hiddenelapsed: hiddenattempt id: hidden
THEME03

The door is the wall弹层是唯一输入通道，修复才反复落空

两次修复都在补 sheet 停放路径，说明缺陷在「弹层是唯一输入通道」这个架构，而不是某一条路径。每次补一条路，门本身还在那里。

WHAT IT PROVES / 非显然的链接

两次修复都停在「sheet 停在哪」，而不是「为什么只有 sheet 能接收输入」。缺陷不在某条停放路径。

弹层是唯一输入通道 —— 这才是那块承重结构。

Only this machine五个外部依赖，先注入再怀疑

FIG. 4 · HYPOTHESIS MAP · NOT A MEASUREMENT
DNS / mDNS本机特异性高 · 排除成本低先注入
keychain / dbus本机特异性高 · 排除成本低先注入
ssh-agent socket本机特异性高 · 排除成本低先注入
GSSAPI / KDC特异性中 · 排除成本中读代码

环境相关性（只有本机卡）最可能落在五个外部依赖上：keychain/dbus、ssh-agent、DNS/mDNS、GSSAPI/KDC、GPU 首帧。前三个特异性高、排除成本低 —— 删掉一个 socket 或换一个无 dbus 环境就能证明或排除。

GPU 首帧成本最高，放最后，用替换法（换机器 / 换合成器）而不是猜。这不是测量，是顺序。

必须用注入排除，而不是猜 —— 这是「本机必现」唯一诚实的处理方式。

A freeze is not slowness.
It is an unowned wait. 卡死不是慢。是没有人拥有这个等待。
