## Intent

**Problem:** The instance module can list, validate, and create instances but cannot delete one, cannot tell whether an instance's server is alive, and `write_last_in` accepts any string — so the guarded delete (CAP-4) and the never-dangling memory rule (CAP-5) have no core to build on.

**Approach:** Add one core delete op (validate, authoritative probe, unlink) with a tri-state dir-scoped seat probe and a refusal/report error shape, plus shape validation inside `write_last_in`, all covered by unit tests including a held-lock refusal test.

## Boundaries & Constraints

**Always:** Layered split (AD-1) — all fs work stays in `tty7-core/src/core/instance.rs`; singleton untouched (probe lives in the instance module); `validate_name` stays the single authority (AD-6); memory rewrite stays the caller's ordered job — core only guards the shape (AD-7).

**Never:** No UI changes in this entry (picker modal/report lands in entry 5); no killing servers; no touching `daemon/singleton.rs`; no new config keys; no pinyin/fuzzy; no trash semantics.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Remove free instance | valid name, no live seat | dir gone, `Ok` | No error expected |
| Remove live instance | seat held (LOCK_EX by live server) | no unlink | `RemoveError::Live` with advisory pid |
| Probe unavailable | non-unix, or lock error (e.g. NFS ENOTSUP) | no unlink | `RemoveError::Unknown`, caller double-confirms |
| Invalid name | `""`, `"default"`, `"-x"`, `"../x"` | nothing touched | `RemoveError::Invalid`, never a path |
| Symlinked dir | `tty7-<name>` is a symlink | nothing touched | `RemoveError::Invalid`, never followed |
| Guarded memory write | `"../x"` to `write_last_in` | file untouched | `io::Error`, invalid input rejected |

</frozen-after-approval>

**Acceptance Criteria:**
- Given a live seat held on an instance dir, when `remove_instance` runs, then it returns Live with the holder pid and the directory still exists
- Given a free instance, when `remove_instance` runs, then the directory is gone and `Ok` returns
- Given an invalid, sentinel, or symlinked name, when `remove_instance` runs, then nothing is touched and Invalid returns
- Given garbage input, when `write_last_in` runs, then the memory file is untouched and an error returns
- Given the full core suite, when `cargo test -p tty7-core` runs, then all green including the new cases
