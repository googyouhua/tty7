topic: Docker 容器作为 tty7 主机类型
updated: 2026-11-01T02:37
---


- (decision) 场景钉死：桌面端在宿主机，容器为长期开发环境（devcontainer/compose），容器无 sshd、无出网，宿主 docker CLI 可用；要完整 workspace（文件/git/多 tab），不做终端降级
- (decision) 技术形状取自仓库现状：RemoteTarget::LocalStdio + RouteHeader::local_stdio + RemoteOps(WSL 实现) 为既有 seam，Docker 复用而非新协议（属 addendum，不进 PRD 正文）
- (decision) PRD 从 initiative-terminal-blocks 迁到新建的 initiative-docker-hosts；active_initiative 一并切换（用户选择独立 initiative）
- (decision) 身份归属定案：容器名即身份，重建即复用 workspace、保留 tab/布局、pane 明示停止（FR-9/FR-10）
- (decision) 执行身份定案：沿用 docker exec 默认（镜像 USER），不做 -u 覆盖，v2 再说（FR-12 相关）
- (decision) 装机定案：首次确认、之后静默自动装，容器重建不再询问（FR-5）
- (decision) Non-goal 定案：无 POSIX shell 的镜像(distroless/scratch)不做——RemoteOps 全是 sh -c 脚本，且无 shell 的容器当终端主机无意义
- (assumption) 同名不同镜像不额外提示，按同一主机处理；待可用性验证，见 Open Question 4
- (decision) 外部研究结论：Zed/DevPod 采用同样的 stdio-over-exec 形状，属外部验证；docker exec 无信号代理使 FR-11(无孤儿) 成为最高风险项
